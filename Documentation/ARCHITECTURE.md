# v0.3规则隔离与兼容

默认设备为`dmc-ver1`，由`DMCV1Engine`和独立JSON实现养成/训练/Quest。`Pet.dmc`记录本阶段计数，`GameState.dmc`记录设备Quest、训练循环和一只备份；存档格式升级为v3。v1/v2迁移不自动改变设备或旧档的规则含义。

`TimeEngine`和`GameEngine`按设备分派；旧训练/战斗/地图入口拒绝接收Ver.1存档。原味界面只显示四心与DP，Quest没有方向坐标和HP。每次整区挑战在事务副本中结算并保存，之后播放记录，避免关闭演出重抽。

原味孵化有独立8秒截止时间，其后分钟游标锚定实际孵化时刻；回前台/定时刷新共享确定性结算。原味死亡基于照顾与伤势，不读取遗留14天寿命。

备份交换与Cold均暂停保存的伙伴。应用设置中的“备份旧档并开始Ver.1”先写独立恢复文件，再保存新档，保留显示选择。

以下为早期公共模块与实验规则的历史说明；与本节不同处，以本节及规则出处为准。

# 架构与维护

## 数据流

SwiftUI → `WorldViewModel` → 时间结算 → 独立领域引擎 → 更新值类型 `GameState` → `SaveStore` 原子写入 → 像素渲染与 UI 刷新。

UI 位于主 actor，领域引擎不使用全局时钟、网络、后台任务或 UI 单例。所有结算函数接收显式 `Date`，PVE 随机状态保存在存档中。纯核心可以在 Linux/macOS 上用同一套 Swift 源码测试；iOS UI 仍必须通过 Xcode 构建验证。

## 时间契约

- `lastTick` 是已结算的分钟边界；只消费完整分钟。
- `highWatermark` 记录最高已见墙钟时间；倒退时保留两个游标，拒绝养成操作。
- 每分钟按固定顺序处理年龄、孵化、睡眠、状态衰减、环境疾病、失误、健康、死亡、进化。
- 分次结算与同一最终时间一次结算的结果相同，包括事件 ID。
- 每只角色最长寿命不超过 90 天；所有存活角色死亡或冷冻后可直接推进剩余游标，因此多年未打开也不会逐分钟运行多年循环。
- 冷冻的宠物不增加年龄；游标仍推进，解冻后不会补扣冷冻期间的养成消耗。
- `homeTimeZone` 固定存于游戏，Calendar 只解释作息小时，不把当地日期字符串当作时间戳。年龄由绝对经过分钟计算，因此夏令时不会凭空多一小时或少一小时。
- 时间正向异常跳变会按真实离线经过时间结算，可能导致死亡；没有服务端可信时间时无法分辨合法离线和人为改时。不承诺本地竞技公平性。

## 存档协议

目录：应用沙盒 `Application Support/DigitalWorld/`。

- `world.json`：当前存档。
- `world.backup.json`：上一次有效存档；首次保存时建立初始备份。
- `world.damaged.json`：首次遇到损坏主存档时保留的原始内容。

外层信封：`format=1`、FNV-1a 64-bit checksum、Base64 编码的 JSON payload。checksum 检测常见意外损坏，不能抵御主动篡改。内层 `schemaVersion=2`；v1→v2 补齐时间水位。未知未来版本拒绝打开，避免降级覆盖。写入使用 Foundation 的 `.atomic`，备份只从已经成功校验的主文件更新。

若主文件损坏则尝试有效备份；两份都无效时显示恢复提示并阻止创建/覆盖存档。错误不会静默重置伙伴。系统磁盘错误会显示提示。应用操作和进入后台时立即保存；前台状态结算至少每 15 秒检查一次、无操作时最多每 60 秒持久化。操作前会先结算已过去的完整分钟。

当前文件读取上限 16 MiB，养成列表上限 32 条；达到档案上限会明确拒绝新一轮重生，尚需后续归档/分页模块。不得在发布前把该限制隐瞒为无限历史。

## 内容扩展

`database.json` 独立于代码，包含 `version`、species、devices、eggs、foods、maps。所有规则引用使用稳定 ID。`ContentDatabase.validate()` 验证重复 ID、引用、阶段方向、时间阈值、战斗数值、地图行宽和规则来源。`validateSave()` 在读写边界验证存档与内容兼容性。

首次登场、家族、官方机型名单等未核实内容保持空/unknown，不通过猜测填满数据。`verifiedFields` 仅列实际核实字段；`balanceProvenance`、进化规则 `provenance`、`artStatus` 明确区分原创参数和归档原版角色像素。

数据中的普通进化支持多个条件并按 priority、规则 ID 确定顺序，只选择第一个符合条件的分支。进化道具一次性消耗；未满足条件不会仅因时间足够而强行进化。特殊进化应作为新规则类型实现、测试、迁移，而不是冒充已由当前普通进化引擎支持。

## 美术契约

每角色独立 PNG，当前为 Digital Monster COLOR 归档图集，64×64 帧画布、12 或 13 列、1 行，保留上游原始 PNG 字节。`sprites.json` v2 按角色定义布局、动作帧索引与播放速度；缺失/空白原图姿态的回退记入 `fallbackActions`。SpriteKit 和图鉴缩略图读取同一配置，采用 `.nearest` 采样，不再假定所有角色共用 3×15 布局。

`sprite-sources.json` 保存原始来源、固定上游提交、SHA-256、尺寸与可用姿态。`Scripts/validate_assets.py` 离线检查字节完整性和非空帧引用。`build_content.py` 只生成规则数据，不能覆盖角色 PNG。新增素材必须附独立来源与许可状态。当前归档来源不是官方发行许可。

新建存档默认 `.color`；读取旧存档保留已保存的 `.lcd`/`.color`/`.advanced` 选择。显示切换只更新设置，不更改角色、养成状态、时间或进化条件。

## 权限与服务

只有用户主动开启提醒时请求通知权限。声音用 `.ambient`，遵循静音。当前不请求运动、健康、蓝牙或网络账号权限；这些模块尚未实现。签名团队由开发者在 Xcode 配置，任何证书或 token 都不进入仓库。

## 开发入口

- `Scripts/build_content.py` 是当前测试内容的生成源；编辑后运行脚本并提交 JSON/PNG。
- `Scripts/generate_project.py` 生成共享 scheme 和工程；新增 Swift 源码后运行并提交。
- Release 不编译 `--ui-testing` 沙盒初始化分支；UI 测试写入独立测试目录，不清除真实游戏目录。
- CI 对自动生成结果做 diff 检查，避免脚本与已提交文件漂移。
