# 阶段与验收状态

本表描述 v0.2 的真实范围。编写代码、核心单元测试通过、模拟器验证通过、真机验收通过是四种不同状态，不能互相替代。

## Phase 1：核心、时间、存档、初代机型

已实现：独立 Swift 核心、分钟步进离线时间、存档校验/备份/恢复/升级、SwiftUI/SpriteKit 应用、初代风格电子宠物外形与 A/B/C 按键。

未完成：严格还原实体 Digital Monster Ver.1。当前唯一开放的 `COLOR LAB / ULTIMATE` 是原创融合规则。Original Mode 通过数据门禁关闭，不能把未核实阈值当作官方条件。

## Phase 2：基础生命周期

已实现：真实时间孵化、喂食与过量惩罚、可操作三次时机训练、排泄、清理、疾病、治疗、睡眠、灯光、冷冻、衰老/死亡、保留记录的重生。数值均持久化。

未完成：实体机特定医疗/寿命差异、厕所训练、注射/药品多种治疗小游戏、孵化完整分镜动画、独立事件音效和背景音乐。

## Phase 3：数据库、进化、图鉴

已实现：版本化独立 JSON，内容与存档校验，8 个角色，基于多条件/优先级的分支进化，道具消耗，图鉴发现/遇见/养成标识，名称搜索，属性与阶段筛选，双轴平移缩放分支图。

未完成：完整官方全角色数据库、全部地区译名复核、全机型名单、按家族/世代/机型筛选、完整官方进化路线。现有路线全部是原创平衡。Baby I/II 的官方属性为空时使用 `unknown`，不擅自标为 Free。

## Phase 4：战斗

已实现：独立、可复现种子的离线 PVE 引擎；属性三角、HP、攻击、防御、速度、命中、闪避、暴击、DP、第三回合特殊攻击；训练和健康影响战斗；记录、受伤、恢复奖励和限回合结束。

未完成：实体机原始战斗算法、互动回合指令、双打、多角色队伍、Boss 机制、锦标赛、排名、在线 PVP、专属技能视觉特效。当前 UI 播放已经保存的文字战斗记录，不能称为完整战斗动画系统。

## Phase 5：历代规则与显示模式

已实现：LCD、彩色、动态光点的高级像素显示；机型数据门禁；27 条目录记录（1 条可玩，26 条待核验的机型组记录）。新游戏默认复古彩色，设置可自由切换经典灰绿色 LCD/复古彩色/高级彩色，屏幕页眉、页脚、场景和角色同时切换；每角色按图集独立配置 15 种游戏动作。

未完成：逐型号独立外壳与游戏规则、全部训练方式、摇摆传感器、特殊进化与临时形态、天气系统、高级角色动画。分组目录不代表组内每个型号已实现。

## Phase 6：世界与任务

已实现：一张原创俯视角地图、障碍碰撞、方向移动、能量消耗、一次性宝箱、野生角色发现、离线战斗入口与碎片任务奖励，数据与养成互通。

未完成：File Island 等指定区域、剧情章节、Boss、多地图传送、隐藏区域与完整探索动画。角色地图标记使用当前伙伴的原版彩色图集。

## Phase 7：通信

尚未实现。没有联网假按钮、假匹配或可用性承诺。后续需要 Game Center、附近连接、配对、可信战斗协议、断线处理与服务端验证。也没有宣称 iPhone 可以直接连接实体暴龙机。

## Phase 8：iOS 扩展

已实现：iPhone/iPad 布局、基础触觉/电子按键音、本地自动存档与系统分享、基础授权通知/安静时段。

尚未实现：iCloud/CloudKit、Widget、Watch App、HealthKit、计步、心率、Live Activities、Dynamic Island、完整多语言。没有索取当前用不到的敏感权限。通知为基础提醒，未覆盖所有养成事件。

## Phase 9：内容

当前包含 8 张 Digital Monster COLOR 角色归档图集，64×64 帧画布，每张 12 或 13 列。上游 PNG 字节完整保留，通过 SHA-256 核验。真实存在的原图姿态用于游戏动作；空白或缺失姿态使用已有原图回退，`fallbackActions` 明确记录。未宣称拥有所有角色的全部官方动画或官方发行授权。

后续：权利审核、完整名单核实、每角色必杀技/受击/进化等精修、追加独立内容包与迁移测试。

## Phase 10：质量与发布

已建立核心测试、内容校验、可重复工程生成、GitHub macOS iOS 构建和 UI 测试工作流。实际运行结果见 Actions 和 `VALIDATION.md`。

发布前尚需真机签名验证、至少一周生命周期测试、性能/内存/能耗测量、VoiceOver 与大字体复核、iPad 全方向体验检查、系统通知实测、数据及素材审查、备份恢复与升级验收。当前版本不适合直接提交 App Store。

## 已知边界

- 时间分辨率为一分钟，不足一分钟保留到下一步；动作影响从下一步开始。
- 离线改时作弊无法在无服务器环境中完全防止。固定时区、时间水位和拒绝倒退只能处理重复结算与部分异常。
- 存档 checksum 用于意外损坏检测，不是签名、加密或防篡改证明。
- 当前采用单活跃伙伴体验和历史列表；不是完整双宠、队伍编辑或 DNA 配对仓库。
- 详细日志每只保留最近 300 条；战斗记录保留最近 100 场；进化顺序永久保留于本地存档。存档限制见架构说明。
- 备份恢复入口会先验证文件，并在确认后保留恢复前的独立备份；系统文件选择器、跨设备文件访问和实际恢复流程仍需真机验收。
