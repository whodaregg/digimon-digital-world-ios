# 28项需求落实与依赖清单

对应[完整需求](FEATURE_REQUEST.md)。当前源码版本v0.6，默认机型仍为用户选定的Digital Monster COLOR Ver.1。下表区分可运行代码、未实现功能和待真机验收；不把机型目录当成已支持的机型。

| 需求 | 当前实现 | 剩余部分或依赖 |
| --- | --- | --- |
| 1.真实功能 | LCD操作调用核心并保存后发布状态；动画只回放已保存结果 | 无静态按钮冒充已实现功能 |
| 2.UI与视觉 | 彩色LCD、右侧A/B/C、8个像素图标、真实像素字体；收藏/设置独立 | 外壳、背景和事件图标为重绘；非逐像素外壳复刻，多尺寸/无障碍仍需设备验收 |
| 3.按键 | A选择/B确认/C返回、防抖、多指组合、按压反馈；A+C切音效、C长按2秒设置、死亡时A+B重生、时钟A+C设置时间 | 长按/组合已接入实际状态；真实多指与触觉待iPhone验收 |
| 4.主页 | 大角色走动/转身/停留/跳跃、进食/拒绝/睡眠/伤势/进化/死亡、排泄物与呼叫 | 无对应原图的眨眼等动作使用声明的已有姿势回退 |
| 5.Status | LCD六个原机分页；增强模式附加战绩/编号，现代详情显示养成数据；经典模式隐藏条件/失误 | COLOR Ver.1没有HP、等级和EXP，不为它编造这类数值 |
| 6.Feed | 肉/蛋白质、原味四心/体重/满腹/过量记录、吃饭与拒绝动作、旧版库存限制 | 其他机型食物需独立规则包 |
| 7.Training | Ver.1五次A/B训练，影响力量/努力/战绩；Core Motion提供Sandbox摇晃输入与A/B替代 | 摇晃输入不是已核验的Pendulum规则；墙壁、蓄力等机型训练尚未完成 |
| 8.Battle | 固定Quest/CPU/BOSS；手机通信确定战果、校验双方、一次消耗与战绩/伤势/进化计数；完整演出 | Tag、Colosseum未实现；Game Center需开发团队能力配置；双机链路待验收 |
| 9.Clean | 按成长时间产生排泄物、累积影响伤势；真实清理、冲水演出和音效 | 不同型号的疾病参数待对应数据包 |
| 10.Sleep | 独立角色就寝时间、08:00醒、关灯、睡眠呼叫/打扰、8小时恢复DP、ZZZ | 其他机型作息未接入 |
| 11.Medical | 原味伤势、按角色多次治疗、恶化死亡、像素治疗反馈 | 非Ver.1疾病机制需各机型数据 |
| 12.Call | 原机宽限/失误判定、图标闪烁、电子音、按同一引擎预测多个设备的本地通知 | 系统送达受iOS控制，真实通知送达待验收 |
| 13.Real-Time | 同一时间引擎按顺序结算离线，保留高水位，倒退时阻止重复奖励；设备时钟设置只改变作息与显示，不快进成长 | 纯离线时钟不是联网可信时间认证 |
| 14.Digivolution | 17种可养成Ver.1角色与分支JSON、截止判定、条件优先级、进化演出 | 其它世代、X抗体与特殊分支缺独立已核验数据；Alter-S仍是NPC/Sandbox指定 |
| 15.Jogress | 当前未开放，不放无效合体按钮 | 需Ver.2等兼容角色/机型规则、合体生命周期与跨版本通信验证；不是把两只同机备份强行合体 |
| 16.Quest | AREA 1～7/F，固定敌人、Boss、顺序解锁、背景奖励、失败重试；每一战演出 | Ver.1不奖励EXP/道具；DMX的XAI、其它机型随机事件/隐藏敌人未接入 |
| 17.死亡重生 | 墓碑反馈、保存最终形态/年龄/战绩/历史；重生继承图鉴，超过32只转入生命周期档案 | 16MiB存档容量保护会在超限写入前拒绝；可导出备份 |
| 18.Sprite | 统一PixelActor/帧时钟、原始图集、最近邻、缺帧回退声明；三种显示与减弱动态效果 | 部分角色缺少独立攻击/眨眼等原图，不能宣称全动作原机逐帧复刻 |
| 19.Device Profile | 机型目录、已验证设备准入、独立规则与角色数据；保留旧实验档兼容 | 目录中的其他世代不能游玩，缺说明书逐项参数/角色/素材包；不会仅换壳宣称支持 |
| 20.Device Collection | 实际新增设备、独立档案/备份、切换前保存、切入补算离线、正式/Sandbox分区 | 当前可新增的正式机型仅COLOR Ver.1 |
| 21.Digidex | 四语角色名、搜索、属性/阶段/设备/收藏筛选、剪影、动画预览、首次获得/次数/完成率、分支 | 旧档未记录的首次日期显示未知；非当前素材包角色未收录 |
| 22.Backup/Freeze | Ver.1仅一只备份/Cold，独立身份与计时、冻结不成长；旧实验多宠保留 | Twin等双宠规则尚未核验，不能在经典Ver.1开放任意多宠 |
| 23.Connection | Multipeer实际发现/邀请/接受/可靠消息；GameKit认证和匹配适配、协议与机型检查、通信收据防重放 | Game Center默认关闭，需团队能力/Bundle ID注册；真机双机/断线验收未完成；实体机物理通信未实现 |
| 24.Settings | 音效/音量/触觉、LCD亮度/对比度/配色/背景、外壳、LCD菜单/角色名四语、通知、备份/导入/重置二次确认 | 错误信息与现代页面部分说明仍为中文；全界面四语翻译未完成 |
| 25.Modes | 经典/增强共用正式规则；Sandbox使用独立文件和虚拟时钟，不计正式收藏，只能与Sandbox对战 | 开发访问码仅本机隐藏开关，不是账号权限服务 |
| 26.Architecture | 原有SwiftUI/SpriteKit/Swift核心保留；新增设备库、输入、动画、通信、提醒、运动模块 | 不为换技术而重写可靠的JSON原子存档；未引入iCloud同步 |
| 27.Data | 角色/动作/食物/规则/进化/Quest JSON、唯一ID、生命周期/通信收据、内容校验 | 已有规则族扩展可走数据；全新训练/战斗机制仍需实现对应引擎，不能只填未经核验参数 |
| 28.交付/验证 | 架构、页面导航、核心、数据、素材、实际操作、测试和依赖清单均随源码提供；已按后续指示发布v0.6.0未签名IPA | 实测结果以[验证记录](VALIDATION.md)为准；签名安装与真实设备验收仍待完成 |

## 无法仅靠当前素材包完成的部分

- 其余世代的逐型号操作、数值、进化、训练、战斗和完整原版素材。目录的“待核验”不是虚构的可玩支持。
- 跨Ver.2联展、实体机通信硬件及协议、双设备并行验收。
- Game Center正式启用需要项目所有者的Apple开发团队与已注册Bundle ID。仓库不包含证书或登录资料。
- iOS17最低系统、不同iPhone/iPad尺寸、触觉、运动传感器、本地网络与通知送达需要真实设备验收。

原版素材、字体和规则依据分别见[像素出处](SPRITE_CREDITS.md)、[字体出处](FONT_CREDITS.md)、[规则来源](RULE_SOURCES.md)。
